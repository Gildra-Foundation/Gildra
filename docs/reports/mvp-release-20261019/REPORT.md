Ещё 21 HTTP-проверка подтверждает скрытые разделы, точные редиректы, отказ анонимному workspace и запрет межсайтовой записи.

На повторной сборке главная/книга дают **0 отличающихся пикселей**, внутренние страницы — **0.00%**. Исходные пороги 0px и 0.5% сохранены; отсутствие эталона теперь завершает проверку ошибкой. Анимации проходят прежние ограничения, включая 4× CPU и полную остановку при reduced motion.

Собраны отдельные [Docker-кандидаты web и Go API](candidate-images.json). Web проверен как standalone-контейнер с файловой системой только для чтения, отдельно с включённым и выключенным staging. После последней серверной правки прошли 28 HTTP-проверок, 12 настоящих браузерных обновлений всех рейтингов и ещё 4 визуальных сравнения тир-листов с 0.00% отличий. Дополнительно проверены смена подземелья без перезагрузки, восстановление заметок и региона недели; доступность хаба логов — ещё 4 представления без serious/critical нарушений.

Образы сохранены для локальной приёмки. У web отключена аналитика/отправка ошибок; для production существующий release pipeline должен собрать артефакт с нужной конфигурацией. Полный образ API собран, а изменённые Go handlers/services проверены в изолированном стенде с PostgreSQL. Production-сервисы не пересоздавались. [Манифест исходных файлов](source-manifest.json) фиксирует 150 изменённых файлов кода/данных относительно исходной ревизии.

Браузерная проверка библиотеки использовала настоящий компонент и дерево талантов, но изолированный workspace transport. Она **не заменяет** вход через Battle.net и проверку реального профиля на двух устройствах. В SQL-тестах использовалась отдельная БД, не production. Необязательная ClickHouse-телеметрия в этом изолированном тесте отсутствовала; атомарность публикации проверена успешно.

## Что блокирует выпуск

1. **Настоящий Battle.net на staging.** Текущий staging намеренно отключает авторизацию. Нужны зарегистрированный callback и защищённая конфигурация отдельного приложения, затем вход/выход/повторный вход, реальный профиль, два устройства и другой аккаунт. [Точные настройки и сценарий](staging-auth.md). Вопрос владельцу задан; ответа пока нет.
2. **Production preflight по отдельной команде.** Перед публикацией нужны свежая успешная резервная копия, проверка восстановления/отката и свободного места. Старый catalog backup ранее завершался ошибкой; здесь успешное восстановление production backup не заявляется.
3. **Совместный выпуск данных и кода.** Боевые tier snapshots пока не имеют нового сезонного контракта. Новый web, Go API и scraper должны выпускаться согласованно; свежие шесть рейтингов публикуются атомарно до проверки сайта. Сохранённый сегодняшний снимок — доказательство локальной приёмки, не команда на боевой импорт.

Production не выпускался. CMS preview/analytics исправления согласованы с параллельной задачей; новый exclusions script требует её nginx-route при соответствующем выпуске. Общая работа с CMS не даёт разрешения на публикацию этого MVP.
