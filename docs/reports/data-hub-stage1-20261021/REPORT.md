## Реализовано

Новый пакет `backend/internal/gamecontent` хранит неизменяемые снимки модулей и комплекты публикации. Миграция `00173_game_content_releases.sql` добавляет семь таблиц `gc_*`, составные внешние ключи и запрет изменения содержимого/истории.

Публикация сериализуется на строке канала и требует ожидаемую generation. Указатель, история и outbox записываются одной транзакцией. Повтор команды идемпотентен. Откат увеличивает generation; устаревшая публикация не отменяет откат. Неполный комплект не может незаметно удалить уже опубликованный модуль. Одинаковое содержимое переиспользует snapshot и release.

Read-only API зарегистрирован в существующем Go server. Публичных HTTP-команд записи нет. Черновики, beta/ptr и закрытые контексты недоступны, включая обращения по известному UUID. Предусмотрены ETag и условный GET.

Локальный CLI выполняет `init-schema`, `import`, `publish`, `rollback`, `serve`. Он работает только с отдельной loopback-БД `gildra_gc_*` через собственную переменную окружения. Текущая production-БД и обычный `DATABASE_URL` не используются.

Runtime reader в `apps/web/lib/data/gamecontent` фиксирует release для рендера страницы и metadata. Он проверяет принадлежность snapshot, изоляцию edition, схему и основные инварианты. При сбое показывает последний целиком прочитанный набор с предупреждением; при холодном старте — unavailable. Достоверный 404 очищает кеш. Даты проверки источников при сбое не меняются.

Существующие представления принимают данные через props; копий шаблонов страниц нет. Подключены RU/EN каталоги, текущие и архивные рейды, боссы, страницы сезонов и канонические страницы подземелий Mythic+. Сезон, ссылки, порядок подземелий и текущий raid slug поступают из публикации. Число боссов — отдельное поле. Порядок карточек рейдов следует массиву каталога и не зависит от сортировки ключей JSONB.

Без `GAME_CONTENT_API_URL` остаётся прежний режим встроенных данных. При настроенном API ошибки не подменяются встроенным набором. Кеш сохранённой версии находится в памяти процесса.

Контексты `retail` и `forever` изолированы; предусмотрены season/phase, независимые каналы и модуль `dungeons`. Реальных данных, источников или страниц Forever этот этап не создаёт.

## Начальный набор

Воспроизводимый offline exporter переносит существующие публичные проекции: 5 рейдов, 18 боссов, 8 подземелий; 5 редакторских обзоров и заметки для всех 18 боссов, spell identities, реальные MDT и прежние статусы полноты/черновиков. Сырые аудиты и скрытые кандидаты способностей в public manifest не входят.

Файл `integrated-seed.json`, SHA-256 `fc2c827c55ebe56b2db8a01a668d579af042c288b4b11f0353bc002edd3ac1cd`. Повторный экспорт совпал побайтно: `seed-reproducibility.json`. Повторный импорт итоговым CLI переиспользовал ту же версию: `final-idempotent-import.json`.

Начальный release в временной БД: `3f8147a2-4693-4c3a-9353-a925fc1070cd`. Статус проверки в игре не повышался; несовместимый импорт Temple of Sethraliss остаётся несовместимым. Начальный bossCount перенесён из прежнего опубликованного route inventory с явным происхождением, а не объявлен новым результатом сбора из журнала.

Даты verification не изменились.

Проверки снятия публикации и сбоя выполнялись до последней правки только порядка карточек; полный браузерный проход и публикация/откат повторены после неё. Браузерные запросы ограничивались loopback, внешние запросы блокировались. Это не проверка настоящего Blizzard OAuth или прохождения в игре.

Сохранились существующее предупреждение ESLint о setState в effect в MythicRouteSelectors, уведомление Sentry о navigation hook и сообщения Next о закрытом потоке при отмене переходов тестовым браузером. Временный запуск через `next start` также предупреждает об `output: standalone`; реальный релиз должен использовать штатный standalone entrypoint. Ошибок pageerror в проверенных браузерных случаях нет.

## Границы и следующий шаг

Первый этап завершён. Не реализованы сбор внешних источников, River jobs, расписание, обработчик outbox, редакторская CMS, правила автоматического одобрения и production writer. Существующие отдельные alias-страницы `/wow/dungeons`, sitemap и изображения Open Graph пока используют прежние механизмы. Новые игровые механики и проекции Forever потребуют собственного адаптера.

Инструкция: [`docs/game-content-stage1.md`](../../game-content-stage1.md). Следующий этап — retail collectors в режиме `collect_only`, сохранение исходных артефактов и diff кандидатов с тестами повторов/ошибок. Автопубликация пока не включается.

Все собственные локальные web/API процессы и временная PostgreSQL остановлены; временная БД находилась на tmpfs. Source, seed, отчёт и доказательства сохранены. Production/staging, аккаунты и их БД этим заданием не менялись. Commit/push/deploy не выполнялись.
