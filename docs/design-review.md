# Дизайн-ревью перед выкаткой (пункт 97) и ежеквартальный аудит (пункт 100)

## Перед каждой выкаткой веба

1. Собрать образ из чистого `git worktree` и поставить его на staging: `sudo sh infra/deploy/deploy-web-staging.sh <образ>` (http://127.0.0.1:3200, читает боевой API, помечен плашкой «Staging»). Для быстрых итераций можно и локальную сборку.
2. `npm run qa:release -- --candidate http://127.0.0.1:3200` — ворота против живого сайта, отчёт в `.artifacts/release-gate/<время>/report.md`:
   - главная и книга — 0 px (`qa:home-gate`, правило владельца);
   - внутренние страницы против живого сайта (`visual:diff`, порог `--max`);
   - доступность: axe WCAG 2.2 AA, контраст текста на арте, видимый фокус, зоны нажатия (`qa:a11y`);
   - бюджет движения и плавность при 4× CPU (`qa:motion`);
   - смоук маршрутов: статусы, ошибки страниц, гидратация (`smoke:routes`);
   - переходы между страницами (`scripts/qa-route-transition.mjs`).
3. Глазами — каждый скриншот с ненулевой разницей:
   - иерархия: один фокус на секцию, заголовок → лид → действие;
   - честный интерфейс: нет выдуманных данных, у незаконченного — `AtlasNotice`/`AtlasEmpty`;
   - арт-герой над сплошным телом, текст читается на картине;
   - телефон 390 px: без горизонтальной прокрутки, цели ≥ 44 px;
   - движение помогает, а не отвлекает; «Меньше движения» выключает всё.
4. Записать выкатку в [docs/releases.md](releases.md), сообщить соседней сессии хеш, выкатить, повторить `SMOKE_URL=https://gildra.net npm run smoke:routes`.

## Раз в квартал

Автоматически: `.github/workflows/quarterly-audit.yml` (1 января, апреля, июля, октября) гоняет
`npm run qa:release -- --candidate https://gildra.net --live` против живого сайта и кладёт отчёт в артефакты.

Руками (по отчёту):

- данные сезона: даты, патч, источники Blizzard на страницах статусов — не устарели ли;
- внешние ссылки (Wowhead, Icy Veins, Keystone.guru) живы;
- `docs/roadmap.md`: статусы и пункты 📊/🔒 — появились ли данные или доступы;
- исключения `atlas:check` (`scripts/check-atlas-tokens.mjs`) — какие уже можно перевести на токены;
- размер образа (`docker history`) и место на хосте; бюджеты маршрутов;
- журнал релизов — откаты, повторяющиеся проблемы.
