# Начало работы для LLM

1. Прочитать корневой `AGENTS.md` — разрешения и правила работы.
2. Прочитать `brand.md` — принятые решения о бренде.
3. Прочитать `design.md` — правила интерфейса.
4. Прочитать `docs/llm/project-map.md` — где искать реализацию.
5. Прочитать `docs/llm/handoff.md` — состояние последней задачи.
6. Проверить Git, актуальную ветку, чужие изменения и доступные команды в `package.json`.

`README.md` описывает запуск и архитектуру. `CLAUDE.md` и исторические документы могут отражать старый интерфейс: при конфликте по визуальному направлению применяются `brand.md` и `design.md`.
Не загружать весь репозиторий в контекст. Сначала найти маршрут, затем компонент, CSS и источник данных.

Для передачи работы использовать `docs/llm/task-template.md`. Обновлять факты и результаты проверок, не записывать предполагаемый успех как завершённую работу.
