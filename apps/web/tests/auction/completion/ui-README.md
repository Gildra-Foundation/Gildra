# Auction completion UI regressions

These tests use the actual current AuctionGearOptimizer in a generated private Next harness with React StrictMode. Characters, market prices, DPS and HTTP jobs are explicitly synthetic. No auth, Blizzard requests or native simulations run. The original reliability tests and old evidence stay in place.

`qa-auction-completion-ui.mjs` requires a local actual-font bundle (`--font-source-dir`, default `.artifacts/auction-completion-20261016/ui/font-bundle`). Its manifest contains four public deployed Inter/Alegreya Latin/Cyrillic file names, SHA-256 digests and their `@font-face` declarations. The runner verifies every digest before copying the files and supplies the same `--font-ui` / `--font-atlas-display` variables as RootDocument. It does not silently substitute missing fonts or fetch fonts from the network. The audit's saved public assets can be copied read-only into this directory; all generated evidence includes the full manifest.

Run from the repository root with Node 22.23 or newer and the installed browser:

```sh
node apps/web/scripts/qa-auction-completion-ui.mjs --phase green --label ui-green-unique --port 58091
node apps/web/scripts/qa-auction-completion-ui.mjs --phase green --legacy --label ui-legacy-unique --port 58091
```

The first command covers EN/RU, 390/1440, locale budget grouping and exact copper precision, incomplete-data refresh in the same search, nonce recovery for lost assembly/resume responses, cancellation before server admission, accepted late POST cancellation/unmount, 409 reconnect, changed exclusions, pending recovery loading, empty/error/focus/overflow states. The second replays the original reliability suite through this actual-font harness. `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` selects a locally installed Chromium when needed.

For red/green evidence, use a fresh `--label` and `--phase red --grep 'regression:'` before product changes. Existing files are never overwritten. The runner binds source hashes for the relevant UI/client files and stops only its own verified private process group; it verifies that the chosen port closed.

Pure parser, client cancellation and recovery-cache assertions run from `apps/web`:

```sh
node --experimental-strip-types --no-warnings --import ./tests/auction/resolve.mjs tests/auction/completion/ui-budget.test.mjs
node --experimental-transform-types --no-warnings --import ./tests/auction/resolve.mjs tests/auction/completion/ui-client.test.mjs
```

The `audit fixes:` cases cover exact-variant exclusion across duplicate auction lots and slot aliases, local-choice recovery after reload, editing while discovery has a pending POST and retiring it before assembly, grouped restoration of 400 duplicate rows, an adjacent disabled-action reason, the explicit `value` / `dps` search objective, and accurate diagnostic copy for significant versus inconclusive maximum-DPS alternatives. A separate legacy regression also pauses pending discovery when excluding a purchased physical lot. Card checkboxes send `excludedVariantKeys` (`JSON.stringify([itemId, variantKey])`); purchase exclusion sends physical-lot slot aliases through `excludedOptionIds`. Both fields participate in recovery and 409 selection matching. The legacy suite still independently verifies physical-lot exclusion across aliases and keyboard restoration.

Excluded groups are mounted only when their disclosure is opened, initially at most 20 groups; duplicate lots of the same exact variant share one restore action. More groups require an explicit “Show 20 more” action. The private fixture contains 400 rows / 200 lots of one exact variant and must render just one restore action after opening.

The `postfix fixes:` cases preserve canonical budget, encounter, objective and selected slots when the first search is still pending, including nonce recovery and a held retirement barrier before any POST. Safe form intent is whitelisted, bounded, and bound to the current character, locale, specialization cache key and profile. Its nonce and form inputs are saved synchronously before waiting for older work; the global active handle is updated only after that older work retires. No prices, item stats or account facts are restored from browser storage. Legacy caches without form intent continue to recover their server-owned handles/results. Invalid intent is rejected; completed server DTOs remain authoritative.

Excluded exact variants reuse `GearPlannerItem` frames/details and show localized level/stat context. Same-name variants with equal or different levels have distinct Restore accessible names, keyboard-pinned descriptions and keyboard restoration. The evidence runner hashes `GearPlannerItem.tsx` alongside the existing seven UI/client files so these presentation changes are bound to each accepted run.

The postdeployment regressions require acknowledged cancellation:503/network failure keeps the exact job/nonce plus a validated `cancellationRequested` intent, exposes Retry cancellation, blocks replacement POSTs, and retries safely after reload. Only acknowledged DELETE (or404 for a known job) clears handles. Unknown-admission nonce404 is not an acknowledgement. Late POSTs still retire behind the existing barrier; recovery/exclusion changes retain ownership until retirement succeeds. Tests also cover a held DELETE, failed prior-scope retirement, preserved existing checkpoints after retry, and localized413 feedback.

Semantic no-ops (Select all with every slot selected, or locale formatting of the same numeric budget) preserve results, exact exclusions and recovery. Real valid changes clear outdated recommendations. Invalid keyboard drafts preserve validated facts and ownership while disabling actions until corrected. Canonical exact variants compact only at the POST wire boundary through `auctionGearSelectionTransport`; internal cache and409 matching retain string keys, legacy keys and physical-lot bans remain unchanged. A browser regression covers compact wire identity plus409/reload. Evidence hashes include the shared transport helper (nine product files).

Real form edits while a request needs recovery also retire its scoped ID/nonce with acknowledgement, even if the global active entry is missing. A validated newer form intent stays alongside those handles. After retirement/reload, owned checkpoint metadata is compared to that intent: a previous budget/slots/objective cannot restore outdated recommendations or overwrite the newer draft. Starting a new search waits for that acknowledgement, and scope unmount cannot dispatch its queued action. The two changed-form regressions cover failed/successful retirement, reload, draft retention and the exact subsequent budget POST.

The final merged-theme UI evidence additionally hashes `app/globals.css` and `app/styles/site-theme.css` (eleven source dependencies). A reload can abort an older keepalive DELETE before acknowledgement; the pending-intent/barrier test now explicitly verifies that the UI stays locked without a POST and retries cancellation when that happens, rather than treating an unacknowledged timeout as success.

The `three-fix regression:` cases additionally cover locale decimal zero suffixes, leading integer zeros and redundant fractional precision as equal monetary amounts. They preserve explicit lot choices, the scoped cache and a completed result without another POST. `budget-canonical.test.mjs` checks idempotent exact decimal normalization down to one copper, zero and maximum-budget boundaries, and retains invalid-input rejection; run it with the same Node/auction resolve flags as `ui-budget.test.mjs` above. The lifecycle regressions hold every cancellation acknowledgement, then truly remove the optimizer or change its keyed snapshot/locale scope before releasing all responses. The retired scope must not start an assembly. A positive mounted-scope control still starts exactly one assembly after acknowledged retirement. No public test route is created.

The stale-ACK continuation of this lifecycle regression keeps an old resume POST held after its cancellation is acknowledged, saves a newer snapshot's input before its first POST, and reloads directly into that same private snapshot. An old acknowledgement must preserve the newer cache byte-for-byte. A retired controller clears saved ownership only when profile, job ID and nonce still match, preserving the latest safe intent/exclusions and checkpoint. `ui-retirement-cache.test.mjs` covers eight exact-ownership, legacy and pending-only cleanup cases; use `--experimental-transform-types` like `ui-client.test.mjs` because the client module includes a TypeScript parameter property.

The late-error lifecycle cases also retire both old and replacement scopes before an old POST returns503 or failed-job DELETE returns200/503. All asynchronous UI/cache updates require the same current request, live scope/generation and unaborted signal; late successful202 still retires its ID and conditionally clears only its captured saved owner after acknowledgement. Failed retired cleanup preserves recoverable ownership. The saved9000-budget replacement must survive byte-for-byte and restore after reload; these are browser regressions, not merely source-text assertions.


The `five-speed regression:` and `five-speed control:` cases cover natural multi-keystroke decimal edits, not just pasted equivalent values. Invalid/empty drafts retain the last validated result, cache and exact exclusions, show localized input feedback, and disable search/assembly/continuation/reconnect/selection. Returning to the same canonical amount resumes without a POST; a genuinely different valid amount invalidates normally. Reload uses only the existing validated saved intent, never the invalid draft. Tests preserve a lost-response nonce and verify no cancellation or duplicate assembly during invalid typing.

Pinned item descriptions are interactive and dismissible at every width, with viewport-clamped positioning after resize, scroll or content reflow. Tests rotate portrait to landscape, exercise short desktop/mobile viewport overflow and wheel scrolling, close/Escape focus restoration, reduced and normal motion, and hover-description boundaries. Evidence now binds fifteen source files: the previous eleven plus WarcraftTooltip.tsx and its characterAuditPage/characterAtlasProfile/gearPlannerItem CSS dependencies. Source mutations during a run still fail its guard.

The `repeat-audit regression:` cases bind restored-completed price warnings to real verification: both expired and still-recent historical jobs stay stale, while a recovered job observed active can publish fresh facts. An open result expires by the same two-hour boundary as the server and is checked again on focus/visibility. Synthetic fixture market timestamps are relative to each test process; controlled-clock expiry tests install the clock before mounting the component.

A keyboard/touch-accessible Change parameters action retires background work with the existing durable acknowledgement, keeps visible results until actual edits and focuses the budget only in the mounted scope after the form unlocks. Rejected acknowledgements keep inputs/actions locked and expose retry. The warm-result clock regression freezes the browser then advances exactly one second, catching a fixed1.5s first poll without machine-speed timing thresholds. The first four polls now use250ms; long native work retains1.5s polling afterwards.

`ui-retirement-release.test.mjs` checks that200 completed Response values are discarded while later barriers still await earlier pending/rejected cancellations. Its boolean assertions deliberately avoid inspecting retained Response internals on RED. `ui-freshness.test.mjs` compares exact age/future bounds to the actual server check. Async persistence regression controls only the debounce timer: real asynchronous catalog turns and compression must coalesce to one latest durable snapshot, and flush must expedite the wait. Admission, atomic writes, publication barriers and their existing race tests remain required.

The real-character repeat gate exposed the former60s catalog lifetime expiring inside a long first calculation. Known public catalog summaries/details now have a bounded5minute lifetime; negative/missing facts keep the60s repair retry. The extra warm-catalog regression advances61s before changing budget and verifies zero redundant summary/detail requests; a separate test still observes metadata repair after5minutes. These caches retain detached raw public facts only: new budgets/slots recompute compatibility, and current price/quantity/availability, character ownership and native engine/variant properties still require their existing fresh verification.

Real repeat profiling also exercises missing-fact refresh calls of30–100ms and native metadata around200–300ms. The checkpoint window is bounded at500ms to combine those turns; final publication expedites it immediately. The deterministic persistence test advances three100ms catalog turns while keeping real async compression/IO, so a shorter ineffective window goes RED. A crash may replay the latest unacknowledged discovery/native work, while acknowledged results and cancellation/admission durability keep their original barriers.
