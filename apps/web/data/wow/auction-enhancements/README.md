# Build-pinned auction enhancement subset

Generated by `python3 apps/web/scripts/build-auction-enhancement-catalog.py` from the existing local catalog using **read-only SQL transactions** and the exact SimulationCraft revision pinned by the project. No imports, migrations, services or purchases. `catalog.json` includes original DB2 row payloads, source artifact UUIDs, build, native source URL/hash, and deterministic SHA256 revision. Candidate IDs come from checked-in profession outputs/ranks, never adjacent IDs or names. Native permanent enchant rules supply ranks and equipment applicability, not consumable mappings.

Confirmed: 75 gem item→GemProperties→SpellItemEnchantment chains, 21 direct consumable→ItemXItemEffect→ItemEffect→SpellEffect(type 53)→SpellItemEnchantment chains, and 88 ranked effect-301 mappings. Example 244643 → 8163 (rank 2); gem 240967 → property 4408 → enchant 8556, category 698/limit 1. Purchased gem simulation IDs are **item IDs**, not enchant IDs.

Ranked mappings have an explicitly separate pinned source build **12.1.5.70783**, from the existing catalog's CraftingDataEnchantQuality. Engine/rules remain **12.1.0.69587**. The generator requires payload parity for the complete Item, ItemSparse, ItemXItemEffect, ItemEffect, SpellEffect, SpellEquippedItems, CraftingData and SpellItemEnchantment chain, and Item.CraftingQualityID must equal the quality row Rank. Every existing field must match; the only tolerated schema addition is explicit SpellItemEnchantment.ItemSquishEraID=0. Missing fields, other additions, changed conditions/stats/levels, missing/ambiguous chains fail closed. Each compatibility proof stores source artifact UUIDs and source-payload hashes. This is evidence of engine-chain compatibility with an authoritative later mapping, **not** a claim that the missing historical mapping table was recovered. Native exact enchant ID + equipment masks supply the displayed rank. No names or adjacent IDs participate.

Semantic closure is compared separately for every mapped item: both builds query **all** ItemXItemEffect rows by ItemID, fetch all their referenced ItemEffect records, then query **all** SpellEffect and SpellEquippedItems rows by the resulting SpellIDs. Equality requires identical `(table,row ID,payload)` sets, including non-applying/secondary effects. New links, extra effects, extra equipped-item restrictions, deleted rows or changed payloads reject that mapping. Later relationship queries are never restricted to old relationship row IDs. Proofs include `semanticRowsetVersion=1` and complete per-table row ID sets; the resolver rejects proofs without that version. This applies a **newer-source mapping to compatible pinned native effects**; it does not prove what the absent historical CraftingDataEnchantQuality table contained.

Real ranked example: Item 244010 → ItemXItemEffect 142170 → ItemEffect 211201 → spell 1236086 → SpellEffect 1231783 (type 301, CraftingData 3827) → source quality row 479 (ItemID 244010, Rank 13, enchant 8020); native rules identify rank 1. Row 480 independently maps item 244011, quality 14, enchant 8021/rank 2. Records expose `mappingBuild`; catalog info exposes `rankedMappingSourceBuild`. Snapshot schema version is now 2.

`auctionEnhancementCatalog.ts` exports:

- `auctionEnhancementCatalogInfo`: version, build, revision (data SHA256), simcRevision, completeness, coverage, missing.
- `auctionEnhancementRecords`, `auctionEnhancementConsumableIds`: exact data subset; consumers must use the resolver to filter restrictions.
- `resolveExactEnhancements(target, character)`: target `{itemId, inventoryType, itemClassId, itemSubclassId, itemLevel, socketColors:[number,number,number], engine, build, revision}`. Target revision means **simcRevision**, not catalog revision. Character `{level, professions:[{id,rank}]}`. Returns `{verified:false,reason}` or `{verified:true,enchantApplicable,enchantChoices,gemChoices}`. Keys of gemChoices are native socket indexes `"0".."2"`; root maps them to its exact socket keys. Only ordinary prismatic socket/color 14 is supported. All three native socket positions must be supplied, including zeros.
- `lookupInstalled(kind, simulationId)`: returns `{verified:true,enhancement}` or `{verified:false,reason}`. For retained native permanent enchants without a purchased mapping, consumableItemId is **0**, never a purchasable choice. Unknown installed gems remain unknown rather than losing category constraints.

Records carry `category?:{id,limit}`, **independent** `uniqueEquipped:boolean`, profession, min/max item level, required character level, native rank (nullable), raw crafting quality ID, and source row references. Root must enforce both shared-category totals and unique item totals across retained and new gems. Resolver verification means supported choices for this exact target, **not** certification of an entire equipment combination or a budget. Profession skill ranks must be actual player facts. Do not infer a rank from CraftingQualityID numerically.

Purchasable records also expose `name` directly from verified `ItemSparse.Display_lang` (source locale `en_US`), suitable as an EN fallback in either UI locale. No translated or ID-derived name is invented. `name` is optional on the shared record type because installed-only native records have no consumable item name.

Native rules distinguish an unsupported scroll mapping from an enchant-inapplicable slot: applicable slots with no supported choices fail `no_supported_enchant`; genuine inapplicable slots can return verified empty choices. Ring/head/chest now have real ranked choices. A reverse ID traversal of uncapped native wrist rules additionally found 5 purchasable mappings for Swift/Safe/Cooled/Shaded Hearthing. These are utility enhancements, **not evidence of DPS gain**. Native stat-wrist rules capped at item level 120/170 remain excluded above that level; do not promise modern wrist combat benefits from these utility records.

Remaining: historical CraftingDataEnchantQuality for engine build 92 is still absent (no matching source artifact); public `https://wago.tools/db2/CraftingDataEnchantQuality/csv?build=12.1.0.69587` returned 403 in the prior source check. Local builds 180/1608 hold the table; only build 1608 is used for the explicit later-mapping compatibility layer. Effect 288 recipes and conditional/special sockets are not resolved. Source tables contain ItemLimitCategory and explicit LimitCategory=0, so ordinary gems no longer have unknown category. Supported nonzero categories require flags=1 and a positive base quantity; conditional enhancements fail closed. Coverage is a subset and must remain visible in result metadata.

Sources checked: local profession builder cache was absent; public Wago/wow.tools/Raidbots exports returned 403. CraftSim generated quality→item data is available but lacks pinned build/enchant IDs, so was not merged. Blizzard versions endpoint is accessible but reports 12.1.5.70783, which was not mixed into 12.1.0.69587. Documented direct catalog access via container IP worked; local 8100 is Plausible, and old api.gildra.net same-vhost redirects to api.wowarcana.com. DB credentials stay inside existing container environment and never enter artifacts/logs.

Validation: `node scripts/quiet.mjs auction-enhancement-catalog -- node --experimental-strip-types --no-warnings apps/web/scripts/test-auction-enhancement-catalog.mjs` and `node scripts/quiet.mjs auction-enhancement-parity -- python3 apps/web/scripts/test-auction-enhancement-source.py`. These are correctness checks, not live DPS or speed measurements.
